Ручная проверка маскирования и восстановления

Один ID связывает исходный текст и его маску. Другой текст с тем же ID вызовет 409. Для отдельного примера создайте новый ID.

Готово к отправке

Запросы выполняются через /process с правами выбранной системы. Исходник и маска хранятся в контексте backend до истечения TTL; панель не сохраняет историю текстов. Для восстановления нужны тот же ID, та же система и точная маска.

ACCESS POLICY

Система

Типы маскирования должны входить в типы детекции. В каждом списке можно выбрать несколько типов. Чтобы отключить обработку всех типов, выберите «Ни одного» в обоих списках. Новые настройки маски применяются к новым payload ID; разрешение демаскирования — также к уже сохранённым сообщениям.
