# Производительность и дополнительные возможности

## Исторические нагрузочные прогоны

Ниже — результаты исходного AlfaGen за 22–23 сентября 2026 года,
перенесённые из документации проекта. Условия этих прогонов отличаются
от локального VibeAlfaGen; производительность конкретной машины нужно
измерять отдельно. При переносе документации новые нагрузочные тесты
не запускались.

### VPS: короткий прогон на 4000 RPS

| Целевой RPS | Время | HTTP 200 | Dropped / failed | p50 | p95 | p99 | max | Итог |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| 4000 | 30 с | 120000 / 120000 | 0 / 0 | 5.38 мс | 35.97 мс | 71.45 мс | 249.67 мс | PASS |

Фактическая скорость с завершением последних запросов — 3990.16 RPS.
Прогон использовал `mask_only`, новые ID и короткие тексты размером
111–117 UTF-8 байт. Генератор работал на той же VPS: 8 vCPU, около 7.7 GiB RAM,
две реплики backend и две Nginx edge, Redis с AOF. Доступ — HTTPS и API-ключ.
Окно генератора — 4096, лимит HTTP-соединений — 128. Перцентили оценивались
по выборке из 1024 измерений; максимум учитывал каждый запрос.

В этом 30-секундном прогоне задержки укладывались в целевой порог 500 мс
при нагрузке выше 2000 RPS. Результат относится к указанному профилю:
он не устанавливает предел VPS, длительную устойчивую производительность
или скорость обработки документов по 100000 токенов.

### Локальные измерения

Среда: Intel Core i5-14400F, Linux/amd64, Go 1.27.1; backend и генератор
на одной машине с Redis 7.4. Запросы шли через loopback HTTP без TLS,
шифрование контекстов Redis было включено. Backend использовал
`GOMAXPROCS=2`, генератор — `GOMAXPROCS=4`; TTL контекстов — 5 минут,
логирование backend — `error`.

| Профиль | План | HTTP 200 | Dropped / failed | p95 | Итог |
|---|---:|---:|---:|---:|---|
| Короткие тексты, 5000 RPS × 30 с | 150000 | 150000 | 0 / 0 | 1.25 мс | PASS |
| Короткие тексты, 8000 RPS × 30 с | 240000 | 239923 | 77 / 0 | 3.15 мс | SLO_MISSED |
| 100000 `cl100k_base` токенов на текст, 1 RPS × 12 с | 12 | 12 | 0 / 0 | 605 мс | PASS |

Последний прогон проверяет обработку крупных текстов: шесть фиксированных
текстов отправлены по два раза. Он не подтверждает тысячи RPS для таких
документов. Токены были посчитаны офлайн; метрика TPS в приложении —
приближение `ceil(UTF-8 bytes / 4)`, а не результат токенизатора.

Движок PII без HTTP/Redis также измерялся отдельно: после оптимизаций
время короткой операции снизилось примерно с 0.727 до 0.334 мс (≈2.2×),
для текста около 400000 UTF-8 байт — с 1.009 до 0.313 с (≈3.2×).
Оптимизации включали предварительный отбор обязательных литералов перед
regex, повторное использование AES-GCM/HMAC и сокращение копирования.

### Как оценить локальный VibeAlfaGen

Текущий Docker-профиль использует один backend, mTLS, TTL 30 минут и
INFO-логирование. Админка устанавливает `concurrency` и `max_in_flight`
в 512. Эти параметры отличаются от исторических нагрузочных прогонов.

Запустите стенд и нагрузку по [README](README.md), затем сравните
фактический HTTP RPS, число dropped/failed запросов и p95 в отчёте админки.
В `round_trip` одна завершённая пара состоит из двух HTTP-запросов.
На время замера исключите другую нагрузку: Grafana показывает суммарный
трафик backend от всех клиентов. p50 на дашборде «Операции» измеряет
PII-модуль по логам; для HTTP-задержки используйте нагрузочный отчёт.

Большие тестовые наборы и инструменты прежних VPS-прогонов не входят в
компактную поставку VibeAlfaGen. Таблицы выше служат историческим ориентиром,
а не готовым обещанием производительности установки из README.

## Дополнительные возможности

| Возможность | Состояние | Где смотреть |
|---|---|---|
| Токенизация и восстановление | Реализовано; маркеры с криптографическим тегом восстанавливаются по сохранённому соответствию | [tokens.go](internal/pii/engine/tokens.go), [processor.go](internal/pii/engine/processor.go), [store](internal/pii/store/store.go) |
| Выбор маскирования по системе | `format` или `token` для `/process`; профиль `strict` и `/v1/generate` используют токены | [SystemConfig](internal/platform/config/config.go), [Processor](internal/pii/engine/processor.go) |
| 2000+ RPS для коротких текстов | Исторически подтверждено на описанной VPS; для текущего Compose требуется собственный замер | Раздел нагрузочных прогонов выше |
| Документы кроме паспорта РФ | Реализовано распознавание водительского удостоверения | [driver_license.go](internal/pii/detectors/driver_license.go) |
| Условное маскирование | Например, PIN маскируется при наличии номера карты в том же тексте | [rules](config.example.yaml), [ruleAllows](internal/pii/policy/policy.go) |
